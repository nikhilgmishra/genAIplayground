# platform/src/knowledge: approved knowledge ingestion and permission-filtered retrieval

Status: **IMPLEMENTED_OFFLINE**. Tested against PGlite (PostgreSQL 17 in WASM with
pgvector 0.8) and against PGlite *without* pgvector. Nothing here has run against
Aurora, Salesforce Knowledge or a real embedding model. This module does not
establish HIPAA compliance or production readiness.

Spec: section 9 ("Approved knowledge and limited memory"), section 3 (retrieved
articles are untrusted input), OPS-06, SAFE-05.

## What is implemented

| File | Responsibility |
|---|---|
| `ports.ts` | `KnowledgeService` port. Added (backward compatible): optional `assurance` on `search()` input. |
| `schema.ts` | Strict zod schemas for `KnowledgeItemInput` and search input; digests; `citationIdFor()`. |
| `sanitize.ts` | Sanitizer for titles/bodies (HTML, scripts, styles, comments, embedded objects, event handlers, entities to a fixpoint, code blocks, inline code, images, attachments, executable file references, `data:`/`javascript:` URIs, markdown/HTML links, raw URLs, bare domains on any TLD, including TLDs followed by decoration such as `-`, `_`, digits or combining marks, and IPv4/IPv6 literals). Entities: numeric references and **every named reference of the WHATWG HTML table** (`html-entities.ts`), matched as a browser's tokenizer matches them (case-sensitive; `;` required except for the 106 legacy names). Normalization (NFKC, IDNA separators folded, every `Cf`/default-ignorable character, U+2800 and every C0/C1 control other than tab and newline removed) runs on the raw input **and again after every entity decode**, so an entity-encoded character (`&#x200b;`, `&#x81;`, `&#xe0049;`, `&#x2024;`, `&shy;`, `&eacute;`, `&copf;`) is treated exactly like its raw form; a reference still decodable after 8 decode rounds fails closed (`ENTITY_DECODE_LIMIT_EXCEEDED`, quarantine) and is removed. The pipeline repeats until its output is a fixpoint; a text that has not settled after 4 rounds (markdown or reference links nested 24 or more deep: each pass rewrites only the innermost link) is quarantined (`SANITIZER_HARD_SCRUB_APPLIED`) and kept only when one more round leaves it unchanged, otherwise emptied. Every output is therefore a fixpoint or `""`, so the sanitizer is idempotent (before this, 25 nested links came back as `[x](t24)` the first time and as `x` the second). The last-resort hard scrub (quarantine `SANITIZER_HARD_SCRUB_APPLIED`) runs at most 16 steps per round and empties the text if it has not settled by then (VSP-KN-02). Allowlisted links survive only as plain text `host/path` (no port, query, fragment or dotted path segment). Inputs longer than `MAX_SANITIZE_INPUT_CHARS` (2 x `MAX_BODY_CHARS`), raw or after any NFKC (including NFKC of entity-decoded text), fail closed with the quarantine finding `SANITIZER_INPUT_TOO_LARGE`. Text hidden in Unicode tag characters, raw or entity-encoded, is returned decoded as `hiddenText` for injection detection. Output invariants (including "no invisible, tag, C0/C1 character and no decodable entity reference") are property-tested with an independent oracle (VSP-KN-01). Trailing punctuation and slash runs are trimmed by backward scans, not `[...]+$` regexes, which are O(n^2) on long runs (VSP-KN-02). |
| `html-entities.ts` | The WHATWG HTML named character reference table (2 125 names, 106 of them legacy names that also decode without `;`), derived from `https://html.spec.whatwg.org/entities.json` and checked entry by entry against an independent HTML decoder when it was derived. Data only; internal. |
| `host-literals.ts` | Detection of bare domains, IPv4 and IPv6 literals with their port and path (VSP-KN-01). A domain is a dotted run (labels joined by runs of `.`, U+3002, U+FF0E or U+FF61) in which some later label, with combining marks deleted, *begins* with 2-63 letters: decoration after the letters (`evil.com-/reset`, `evil.com_`, `evil.com1`, `evil.co\u0332m`, `xn--` A-labels) does not hide the TLD. Percent escapes are read **both ways**, decoded as a URL parser decodes them inside a host and as written, and a literal any reading finds is reported. The decoded readings keep the text's length, so offsets stay valid: each escape (one byte, or a well-formed UTF-8 sequence) is folded as the sanitizer folds the raw character (NFKC, IDNA separators as `.`, characters the sanitizer removes deleted, any other non-label character a break) and padded with combining marks, which classification deletes. An escape that folds to separators only (`%2E`, `%E3%80%82` for U+3002, `%EF%BC%8E`, `%E2%80%A4`) becomes as many `.`, scanned rather than matched as a pattern alternative, whose `2E` label characters would let a long `%2E%2E...` run start one attempt each (quadratic); `%6F`, `%C3%B3` and `%EF%BD%83` read as `o`, U+00F3 and `c`; `%E2%80%8B`, `%C2%AD` and `%C2%85` as nothing; `%C5%80` (U+0140, NFKC `l` + U+00B7) as `l` and a break; and `%20`, `%2F` and `%25` as a break, as the raw character is (kept as written, the `2F` of `%2F203.0.113.7` hid the IPv4 literal). Separator escapes and the other escapes are decoded separately and together, so `billing-portal%2Ec%6Fm` and `billing-portal.%63%6F%6D` (billing-portal.com to a URL parser, which the `%2E`-only reading served end to end) are domains, while the text as written still makes `%2E.com/pay` the host `2E.com`, `%2E::` the IPv6 literal `2E::`, and `%2Eportal.synthetic-health.test` the non-allowlisted host `2Eportal.synthetic-health.test`, so the allowlisted reading behind it does not keep the span. A host spelled with an escape is never the allowlisted host. A text holding a percent escape is scanned once per distinct reading (at most four), and each escape is decoded once per text. IPv4: four or more numeric labels (decimal or hex, optionally decorated with `-`/`_`). IPv6: `::` or eight groups, optionally bracketed (every reading here too: `%2Effc::1`, `[%2E::]`). Linear time: literals inside an earlier literal's path are still reported (the re-check needs them), so the path end is memoized instead of rescanned per literal (VSP-KN-02). Internal. |
| `markup.ts` | Linear-time element pairing (`replaceElements`) and `<tag ...>` replacement (`replaceTags`) with exactly the semantics of the former lazy cross-tag regexes, which backtracked in O(n^2)/O(n^3) on unterminated markup (VSP-KN-02). Internal. |
| `injection.ts` | Prompt-injection and dial-target detector (instruction overrides, role markers, persona switches, transfer/tool/secret directives, phone numbers, dial/press/extension instructions, `tel:`/`sip:` URIs) with Unicode/confusable folding. Invisible and C0/C1 control characters are removed before matching (`ig<U+200B>nore` matches). ### Ingestion rules (per item)

1. Strict structural validation (unknown fields fail: `KNOWLEDGE_SCHEMA_INVALID`; missing/blank owner: `KNOWLEDGE_UNOWNED`).
2. Sanitize title and body. Executable or embedded content (`<script>`, `<iframe>`, event handlers, `javascript:`/`data:` URIs, fenced code, executable attachments) => quarantine `KNOWLEDGE_EXECUTABLE_CONTENT` (+ the specific finding). An input the sanitizer refuses as too large => quarantine `KNOWLEDGE_SANITIZER_INPUT_TOO_LARGE` (+ `KNOWLEDGE_EMPTY_AFTER_SANITIZE`). Unicode tag characters, raw or entity-encoded => quarantine `KNOWLEDGE_HIDDEN_TAG_CHARACTERS`; entities nested deeper than the decode budget => quarantine `KNOWLEDGE_ENTITY_DECODE_LIMIT_EXCEEDED` (neither adds `KNOWLEDGE_EXECUTABLE_CONTENT`). Formatting and links (including bare domains and IP literals) are stripped and recorded but do not quarantine.
3. Injection / dial-target detection on the raw input, the input with entities decoded to a fixpoint (markup kept; NFKC before each decode, so a fullwidth `＆#x69;` inside a comment is decoded as the sanitizer decodes it), the sanitized output **and** the text hidden in tag characters (raw or entity-encoded) (an instruction hidden in a stripped HTML comment still quarantines). Knowledge can never carry a dial target (SAFE-05).
4. Personal-data patterns (email, SSN-like, Luhn card-like) => `KNOWLEDGE_PERSONAL_DATA_PATTERN` (not a blind paste of operational documents).
5. Policy: `APPROVED` with approver and time (not in the future); not expired; already effective; valid window; a `public` audience requires `PUBLIC` sensitivity.
6. Versions: a stored `(sourceId, version)` is immutable (application check + DB trigger `KNOWLEDGE_VERSION_IMMUTABLE`); versions older than the newest stored are `KNOWLEDGE_VERSION_STALE`; a live new version supersedes older ones; re-ingesting a live version as `REJECTED`/expired takes it out of service immediately; re-ingest of identical content is idempotent.
7. Conflicts: two different sources sharing an intent and an audience, same language and jurisdiction, overlapping windows and different content digests. With an **approved** precedence order (`{order, approvalRef}`) across different source systems, the lower-precedence item is held (`KNOWLEDGE_CONFLICT_LOWER_PRECEDENCE`); otherwise **both** are held (`KNOWLEDGE_CONFLICT_HELD_FOR_REVIEW`), including an already-live stored item. Holds are released only by `releaseHeld()`/`rejectHeld()` (MFA `knowledge_editor`).
8. Snapshot of the servable set; a new snapshot row only when the set changes. Optional audit event `knowledge.ingest` in the same transaction (audit failure => nothing ingested, OPS-01).

Structurally valid rejects are stored as quarantined review records (never servable; no embeddings); `reviewQueue()` lists metadata only (no bodies) and sets the catalogued gauges `vsp_knowledge_items_needing_review` / `vsp_knowledge_freshness_age_seconds`.

### Retrieval rules

* Runs as `app_runtime` with tenant RLS; the RLS policy itself exposes only servable rows.
* Filters (tenant, approved, not quarantined/held/superseded, effective window vs the supplied `now`, permitted intent, language with primary-subtag fallback, jurisdiction with country fallback for `US-XX`, audience) are applied in the `permitted` CTE **before** ranking and `LIMIT`.
* Audience: `audience: "public"` or `assurance: "A0"` => only `PUBLIC` items listing `public`. Otherwise public items plus items listing the caller's server-established role.
* Every returned row is re-checked in TypeScript (same predicate), its content digest is verified, and the served text (title **and** excerpt) is re-checked by the injection detector and the sanitizer invariants (`servedTextSafe`): `sanitizedTextViolations` checks angle brackets, `://`, `www.`, executable and `data:` URIs, bare domains on any TLD and IP literals on **two readings** and reports the union: the text as stored, and the text normalized, entity-decoded and stripped exactly as the sanitizer does. The second sees a host an invisible, control or entity-encoded character splits; the first sees what NFKC destroys before the second looks (`<` + U+0338 composes to U+226E, and `evil⑴.com` becomes `evil(1).com`, no host), which a re-check that read only the normalized text served, with a literal `<`. It also flags any invisible, default-ignorable, tag, C0/C1 character or decodable entity reference (numeric or any name in the HTML table, as written or after NFKC: a stored fullwidth `＆#x200b;`) left in it; the whole stored body is also checked for such characters. Text the sanitizer writes is a fixpoint of its own normalization, so the stored-text reading adds no finding to it (fuzz-checked: rows built from sanitizer output are not dropped). A row stored by an older sanitizer (a host split by U+206A, U+061C, U+FFF9, U+200B, U+0081, tag text, or an entity-decoded U+2024; a host spelled with a named reference such as `caf&eacute;.com` or `&copf;&oopf;&mopf;`; a title that holds only tag characters, U+200B, a C1 control or a literal `&#x200b;` or `＆#x200b;`; a host led by `%2E` such as `%2E.com/pay` or `[%2E::]/pay`; a host spelled with other percent escapes such as `billing-portal.%63%6F%6D/pay` or `evil%E3%80%82com`), and a row written by no sanitizer version (a raw `<` + U+0338, `evil⑴.com/pay`), is therefore dropped (`RECHECK_EXCERPT_UNSAFE`), logged and counted. An ampersand that starts no reference (`HR&IT`, `R&D`) does not drop a row. Because a stored version is immutable, re-ingesting the same version with the new sanitizer output is quarantined as `KNOWLEDGE_VERSION_IMMUTABLE`: such an article needs a new version.
* Hits carry `citationId = kb_<sourceId>@v<version>` (exact version) and a bounded sanitized excerpt. Sensitive facts must come from structured tools, not from knowledge.
* Customer transcripts are never stored or embedded here.

## Known limitations

* Invisible and control characters (VSP-KN-01): every Unicode format character (`\p{Cf}`),
  default-ignorable code point and U+2800 BRAILLE PATTERN BLANK (a blank filler that is
  not whitespace) is deleted before matching (`stripInvisible`), and so is every C0 control
  other than tab and newline, DEL and every C1 control U+0080-009F (`stripControl`; both in
  `platform/src/privacy/patterns.ts`, shared with injection detection, search-query
  normalization and PHI redaction). The deletion runs on the raw text and again after every
  entity decode, so neither raw nor entity-encoded characters can split a host. Unicode tag
  characters (U+E0000-E007F), raw or entity-encoded, additionally quarantine the item
  (`HIDDEN_TAG_CHARACTERS`) and their decoded text is run through injection detection.
  Injection detection reads every hidden character as nothing, and only the characters that
  can stand for a word break (C0/C1 controls, U+200B, U+2060, U+FEFF, U+2800, U+3164, U+FFA0)
  also as a space; `ignore<U+00AD>previous` (a soft hyphen, which renders as nothing) is read
  as `ignoreprevious`, which is also what the stored text says.
  Tests: `src/knowledge/sanitize.invisible.test.ts`.
* Rendering effects on prose: what is removed is every format (`Cf`) and default-ignorable
  character, U+2800 and the C0/C1 controls; letters, digits and accents outside those classes,
  CJK, Arabic and Syriac letters, skin tones and regional-indicator flags are unchanged. Some
  removed characters render, so some text renders differently:
  - Visible format characters: the prepended concatenation marks U+0600-0605 (Arabic number
    signs), U+06DD ARABIC END OF AYAH, U+070F SYRIAC ABBREVIATION MARK, U+0890-0891, U+08E2 and
    the Kaithi number signs U+110BD and U+110CD draw a sign across the digits or letters after
    them: the sign disappears and the digits stay. The Egyptian hieroglyph format controls
    (U+13430-1343F) are removed, so hieroglyphs lose their quadrat layout.
  - Default-ignorable letters and marks: the Hangul fillers U+115F, U+1160, U+3164 and U+FFA0
    (an archaic syllable written with a filler loses its placeholder) and the deprecated Khmer
    inherent vowels U+17B4 and U+17B5 are removed; U+2800 (a blank braille cell) is removed, so
    braille words it separated are joined.
  - Joiners and selectors: ZWJ/ZWNJ removal splits emoji ZWJ sequences into separate glyphs
    (family, profession, rainbow flag) and changes Persian and Devanagari shaping where they
    were used; VS16 removal turns emoji presentation into text presentation (U+2764 U+FE0F
    becomes U+2764, a keycap loses U+FE0F); Mongolian free variation selectors are removed.
  - A subdivision flag (England, Scotland, Wales) is built from tag characters: it becomes a
    plain black flag and the item is quarantined `KNOWLEDGE_HIDDEN_TAG_CHARACTERS`, a false
    positive that fails closed (a human reviews the item).
* Entities: numeric references (`&#x` + up to 6 hex digits, `&#` + up to 7 decimal digits, `;`
  optional) and every named reference of the WHATWG table (`html-entities.ts`) are decoded, with
  the HTML tokenizer's matching rules. Names are case-sensitive (`&Lt;` is U+226A, not `<`;
  `&IT;` and `&Amp;` are not references). `;` is required, except for the 106 legacy names
  (`&amp`, `&lt`, `&gt`, `&quot`, `&nbsp`, `&shy`, `&copy`, `&reg`, `&not`, `&eacute`, ...),
  which, as in a browser, are decoded without it even inside a word: the longest legacy
  prefix wins (`&notit;` becomes `¬it;`, `Health&regulations` becomes `Health®ulations`). An
  ampersand that starts no reference (`HR&IT`, `R&D`, `Q&A`, `Rock&Grave`) is left as written.
  An earlier 60-name table, looked up case-insensitively with `;` optional, left
  `caf&eacute;.com` and `&copf;&oopf;&mopf;` (NFKC `com`) as literal text that hid the host and
  turned `HR&IT` into `HR` + U+2062. Because decoding repeats to a fixpoint, double-encoded
  text is decoded twice (`&amp;eacute;` becomes `é`, where a browser shows `&eacute;`): a
  deliberate over-decoding so that encoded markup cannot survive. Numeric references are
  decoded to their code point (a browser maps `&#128;`-`&#159;` to Windows-1252 punctuation;
  here they are C1 controls and are removed). A reference still decodable after 8 decode
  rounds in one pass fails closed (`ENTITY_DECODE_LIMIT_EXCEEDED`, quarantine) and is removed
  from the text.
* Conflict detection is mechanical at the (intent, audience, language, jurisdiction) granularity; complementary articles for the same intent and audience are also held. That is conservative by design; a human releases them.
* The injection detector is heuristic (no spelled-out digits, no deep obfuscation such as letter-spaced words). Retrieval therefore treats excerpts as untrusted data, and transfers use allowlisted destinations only.
* Domain detection is deliberately broad (any dotted run in which a later label begins with 2-63 letters, whatever follows them): dotted identifiers such as `Node.js`, `statement.pdf` or `build.rc1`, a sentence typed without a space after its full stop, and words joined by an ellipsis with no space (`wait...what`) are removed as domains (STRIP-level `URL_REMOVED`, not quarantine). Because U+3002 is an IDNA label separator, CJK prose joined by an ideographic full stop with no following space is removed the same way; CJK is not a supported knowledge language today.
* Not detected: spelled-out or spaced addresses ("evil dot com", `evil . com`, "hxxps colon slash slash"), including labels split by a visible line break (newline, U+2028 LINE SEPARATOR, U+2029 PARAGRAPH SEPARATOR: the reader sees two separate lines); bare single-integer IPv4, decimal (`3405803783`, which the dial-target detector's long-digit rule quarantines anyway) or hex (`0xCB007107`: treating an `0x` + 8-hex-digit token as an address would also remove ordinary error codes such as `0x80070005` from support text), and two- or three-part shorthand IPv4 (`127.1`); a "TLD" longer than 63 letters (not a DNS label); percent escapes decoded more than once (`%252E` is the text `%2E` after one decoding, which is what a URL parser does; it is not read as a separator), and malformed, overlong (`%E0%80%AE`) or surrogate UTF-8 escapes, which a URL parser rejects and which are only read as written; an IPv6 literal with escaped hex digits or colons (the padding after each decoded digit or colon ends a group, so `%66%66::1` loses only the `66::1` the text as written shows, and `%3A%3A1` or `%E2%A9%B4` (U+2A74, NFKC `::=`) is no IPv6 literal; a URL parser does not percent-decode a bracketed IPv6 host); a line break written as an escape (`%0A`, `%0D`), which is a break like the raw line break; an IPv6 literal with a combining mark inside a group (`ff\u0301::`: the mark ends the group, and a bare `::` is not an address; with a group after `::`, as in `ff\u0301::1`, the `::1` part is still removed); and TLD labels that *start* with `-`, `_` or a digit (`evil.-com`, `evil.1com`), because treating that as decoration would also remove `U.S.-based`, `9.30am` and `2.5GB`. Look-alike separators that are not IDNA label separators (U+00B7 middle dot, also written `&middot;` or `&centerdot;`, U+06D4 Arabic full stop: `evil\u00b7com`) are not treated as dots. A character that is neither a separator nor a label character after the TLD (U+2010 hyphen) ends the run, so `evil.com` is still removed from `evil.com\u2010/x`. The same character *before* the dot (`evil\u2010.com`) also ends the run, so that form is left as text; it is not a resolvable hostname as written. Long digit runs are covered by the dial-target detector.
* Sanitization has no wall-clock deadline (its output feeds content digests and must stay deterministic). Time is bounded instead by linear-time patterns plus the input cap. Measured on a developer machine (best of three): the slowest adversarial units (repeated markdown image/link openers) take about 65-100 ms at 20 000 characters and about 135 ms at 40 000; host+path units (`a.bc/`, combining-mark `a.bc/`, IPv4/IPv6 with paths) take about 5-15 ms at 40 000 (they took up to about 1.1 s before the VSP-KN-02 round-2 fix); `evaluateKnowledgeItem` on a schema-maximum body that NFKC-expands to 35 001 characters takes about 10 ms (about 760-850 ms before). Tests enforce a strict 100 ms budget for host+path units at 20 000 and 40 000 characters and for punctuation-run, slash-run and NFKC-expanding bodies of up to about 40 000 characters after NFKC, 50 ms for `hostLiterals` alone at 20 000 and 40 000 characters, and a coarse 1.5 s budget for the markup units. The per-start work of the capped link patterns is bounded by their 2 000-character target cap, so the constant factor, not the growth, dominates their time. Normalization now also runs after every entity decode (at most 8 decodes per pass, 6 passes per round, 4 rounds plus one round that only confirms a fixpoint), a text holding percent escapes is scanned for hosts once per distinct reading (at most four), and the retrieval re-check scans the stored text and its normalized, decoded reading; a growth-ratio test (sanitizer 5 000 -> 40 000 characters below 24x, re-check 10 000 -> 160 000 below 48x, against about 8x and 16x when linear and 64x and 256x when quadratic) covers entity-encoded, named-reference (full table, longest-match legacy names), percent-escape (`%2E`, including `%2E.` and `%2E.bc/`, which the raw reading scans; escaped letters `a.%62%63/`, `a%2Eb%63/`, the UTF-8 separator `a%E3%80%82bc/`, the escaped invisible `a.b%E2%80%8Bc/`, malformed `%E3%80` and the break `%2F1.2.3.4/`), C1 and U+2800 units and a hard-scrub chain. The strict budgets and the growth ratios measure the CPU time of the test process (`process.cpuUsage`), not wall-clock time, so other processes on a loaded runner cannot inflate them (with wall-clock time, three suites run at once failed them on unmodified code); and each ratio is measured again, interleaved and keeping the best time per size, up to five attempts until it is under its threshold. The thresholds are unchanged, so a quadratic step (an unbounded hard scrub, a path scan without its memo, a quadratic escape scan) still fails every attempt. The hard scrub used to loop until nothing changed, so a chain in which each removal exposes one more construct (`"data:".repeat(k) + "text/plain, ".repeat(k)`) cost O(k * n): about 15/55/207/890 ms at 5 000/10 000/20 000/40 000 characters. It now stops after 16 steps per round and fails closed with an empty text (the item is quarantined anyway): about 3/6/12/33 ms. Because a timing test can blur on a loaded runner, a deterministic test also checks that a 40-deep chain followed by prose comes back empty (an unbounded scrub kept the prose).
* The local embedder is lexical; it does not provide semantic recall.
* `releaseHeld()`/`rejectHeld()` execute as `app_worker` with the staff id in the RLS context (the console module owns the staff-facing endpoint).

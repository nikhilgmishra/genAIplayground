# Layer-2 composition suite (WP-07)

The live composition root (`platform/src/main/live-container.ts`, `live-worker.ts`, `live-console.ts`) composed
in the **sandbox** profile against the local emulators, with production code only. Run it with:

```
make up PROFILE=core
make test-integration SUITE=composition
make test-integration SUITE=composition FILTER=no-dev-bypass
make test-integration SUITE=composition FILTER=approval-trust
make test-integration SUITE=composition FILTER=secret-separation
```

## Test plumbing (labelled, not fakes of what is under test)

- SYNTHETIC host names under `example.com` (RFC 2606) mapped by the sandbox-only resolver of the live container
  (`network.resolve`) to the compose bridge address, where a TLS front proxy (Keycloak), the vendor emulator or
  the collector listens with a per-run test CA (`network.tlsCa`). The transport's address-class, allowlist,
  egress and TLS checks all apply; staging and production refuse both overrides.
- The caller's verified state in `faults.test.ts` is written through the production `SessionStore` because
  caller verification is NOT_CONFIGURED in this build (identity.caller, WP-19).
- `worker.test.ts`: recording topic handlers stand in for the business module's consumers (a port of the loop
  under test); the real `action.committed` consumer is used too. `no-dev-bypass.test.ts`: `RecordingListener`, a
  plain HTTP listener that records method, `X-Amz-Target` and whether an Authorization header carried a
  credential (never its value).
- `SessionExpirySeam.wrap` refuses every environment but local/ci (fault seams never run deployed): the test wraps
  it with `ci` and hands it to the sandbox container as its clock.

## Emulator fidelity findings (WP-07)

- LocalStack 4.14 KMS answers `GetPublicKey` for a **disabled** key (AWS refuses it with DisabledException);
  `Sign` is refused. A key pending deletion is refused by both, so the key-unusable injections use
  `ScheduleKeyDeletion`.
- `docker0` has an address only while a container uses the default bridge: a private-interface address taken from
  it can vanish between two calls of one test. `privateInterfaceAddress()` prefers the compose bridge (`br-*`),
  and the telemetry test pins the resolver to the address the collector was published on.
- ElasticMQ 1.7.1 does not store a per-queue maximum message size (WP-04 finding); the DLQ_FULL seam uses a
  deleted queue (`QueueDoesNotExist`).

## What this suite does not prove

The audit exporter unit (`main/audit-exporter.ts`) has no Layer-2 run here: its export and verification logic is
WP-04's Layer-2 `substrate/audit-export.test.ts`, and the unit's own composition (mode, refusals, and the guard
inputs it shares with the gateway, under which a complete staging configuration passes the full rule set) is
covered by the unit test `src/main/audit-exporter.test.ts` (which also starts the unit's guard over a scratch
configuration directory and shows it refused when another committed environment's signing key is this environment's
anchor or manifest key). It builds its own AWS clients and database pool; it
does not reuse `buildLiveContainer`. HTTP request tracing (not emitted yet). A real prepare and a commit that
reaches a provider in the AUTH_EXPIRY fault run (no live scheduling adapter, WP-23).
Real AWS IAM, VPC endpoints, KMS key policies and Secrets Manager rotation; a real tenant IdP, vendor sandbox or
Talkdesk account; the ALB/WAF in front of the units; production capacity. Every capability whose live adapter does
not exist yet (business systems WP-23, relationship directory and caller identity WP-19, notifications WP-27,
Talkdesk WP-28/WP-29) is NOT_CONFIGURED here by construction.

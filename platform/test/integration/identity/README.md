# Layer-2 suite: caller and workforce identity (WP-05)

```bash
make up PROFILE=core
make test-integration SUITE=identity
```

The production identity path against the local composition: OpenID Connect discovery, the relying-party
client and the ID-token verifiers over the WP-06 egress-classified transport (TLS, pinned host, no
redirects) to Keycloak 26, console sessions on postgres:16 (every migration), caller sessions on DynamoDB
Local. Nothing here uses a LOCAL FIXTURE IdP, PGlite or an in-memory session store. Every realm is created
through the admin API under a unique realm name and deleted afterwards; the shared Keycloak is never
restarted or reconfigured. Realm names use a letters-only random suffix (`realmName`): the production
EgressGuard refuses URL paths with a long digit run or a Luhn-valid number, and the former hex suffix
tripped it for about 2 % of names (6 realms per run: about 11 % of runs failed after 60 s with
`OIDC_PROVIDER_UNAVAILABLE`, earlier misattributed to shared Keycloak load). `realmName` asserts the
resulting discovery URL passes that check, and `waitForRealm` now fails at once, with the reason, on any
non-retryable refusal instead of retrying it for 60 s.

Helpers (`support.ts`): a per-run test CA (`openssl`), `IdpTlsProxy` (serves the shared Keycloak as
`https://idp.vsp-identity.test` with the test CA, because the production transport refuses loopback and IP
literals), `liveOidc` (production adapters over that front), `waitForRealm`, realm representations with
pre-provisioned TOTP credentials, the `amr` / `groups` mappers and a client role mapper (`vsp_roles`, the console client's roles each managed group grants: `realmRep({ groupClientRoles })`), a minimal user agent (`Browser`) that
submits the password (also the password-only re-authentication page) and OTP forms, counts the forms it
submitted and stops at the redirect, a DynamoDB session table per run and a
stand-in account directory and link capture labelled `local_fixture` (the caller account directory has no
live adapter yet; the system of record and the delivery channel are not under test). `gateway-support.ts`
composes the production tool pipeline with two labelled Layer-2 test tool modules (a protected read over
`appointment:read`, a human route over `human:request`) and a relationship stand-in.

Fault injection points built here: **AUTH_EXPIRY_IDLE** and **AUTH_EXPIRY_MID_CALL** use
`SessionExpirySeam` (`platform/src/identity/expiry-seam.ts`; refused outside local/ci); WP-07 owns the
end-to-end `[FAULT:AUTH_EXPIRY_MID_CALL]` run (prepare, expiry, commit refused). **IDP_UNAVAILABLE** stops
the test's own TLS front (the shared Keycloak keeps running).

Fidelity notes (also in `docs/adr/proposed/WP-05-workforce-sso.md`): Keycloak 26 OMITS the `groups` claim
(ID token and refresh-token introspection) for a user without groups, it never sends `[]`; a realm's `frontendUrl` sets the issuer,
authorization and end-session endpoints, back-channel endpoints follow the forwarded `Host`; Keycloak's SSO
cookie signs the previous user in again in the same user agent (one agent per login, except the `max_age`
case, which keeps one agent on purpose); RFC 7009 revocation of one sign-in's refresh token leaves the
user's other IdP sessions active; with `revokeRefreshToken` and max reuse 0 a refresh token Keycloak has just
redeemed introspects inactive before the console records the rotation (so a logout racing its own refresh sees an
inactive token and, fail closed, suspends the custodian), and revoking that redeemed token ends its successor too; a top-level group whose name contains `/` gets the same full path as a
nested group (group paths are not unique, so the console maps client roles); amr lists only the labelled
authentication steps; the first discovery of a new realm can exceed three seconds under shared load
(ten-second test timeout, `waitForRealm`).

What this does not prove: any tenant IdP's configuration, amr values, group names or MFA enrolment; the
portal application's own OIDC client (outside this repository); DynamoDB TTL or IAM (DynamoDB Local); a live
caller account directory (account linking `(iss, sub) -> actor` runs over the labelled stand-in); the
composed gateway container and the `EvaluationResult` record of a fault run (WP-07, WP-34).

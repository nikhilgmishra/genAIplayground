# WP-23 threat rows (draft, phase C): canonical domain contracts, live domain adapters, reference business API

Drafted by WP-23 for its boundary (the domain adapters and commit port in `platform/src/domain`, the reference business
API in `services/reference-business-api` with its compose fragment `deploy/local/services/reference-business-api.compose.yaml`,
and the Layer-2 suite `platform/test/integration/domain`). The phase C threat-model owner (WP-17) merges them into
`docs/security/threat-model.md` section 8 with FT ids. They refine the action rows (ACT-01 to ACT-03), the authority
rows (AUTH-02, AUTH-05) and the connector rows of WP-06 for domain effects; the action contracts and EffectVerification
ownership move to WP-25 in phase D.

Round 1 refix (wave C1): rows T-FO-23-03, T-FO-23-04 and T-FO-23-09 claimed mitigations that the verifier's probes L1
(a write held behind a row lock and applied after the platform concluded "not found"), L2 (a business-layer port that
took the acting party from the record, a confused deputy) and L3 (one request id reused with another payload, answered
with the first action's receipt) defeated. They are restated below with the mitigations that now hold, the tests that
show it, and honest statuses. Rows T-FO-23-10 and T-FO-23-11 are new.

Round 2 refix (wave C1): the round-2 verifier falsified T-FO-23-03's claim that "a request id absent after notAfter can
never apply later": a COMMIT delayed after the final deadline check (probe commitlatency C1-C3) landed after the
platform had decided NOT_FOUND. The deadline is now liveness only; absence comes from the system's fence (rows
T-FO-23-03, T-FO-23-12). T-FO-23-02 (a legacy duplicate inside the lookup lag, probe legacylag) and T-FO-23-10 (the
command path committing a client kind with a caller-chosen expiry, probe U1) are restated; T-FO-23-13 is new.

# Activation register

One register of every external input or authority the follow-on product needs before a capability can leave `NOT_CONFIGURED`: credentials, BAAs, approvals, tenant configurations, staffed routes, paid tests, PHI processing, vendor entitlements, model access and legal reviews (prompt sections 0 and 19, `ACTIVATION_REGISTER`). Machine-readable form: [`followon/activation-register.yaml`](followon/activation-register.yaml), generated by [`tools/followon/generate.py`](tools/followon/generate.py); capability ids: [`followon/capabilities.yaml`](followon/capabilities.yaml). Prerequisite records: [`prerequisites.yaml`](prerequisites.yaml) and [`PREREQUISITES.md`](PREREQUISITES.md); approval records: [`../approvals/README.md`](../approvals/README.md); approval requests: [`release/approval-requests.md`](release/approval-requests.md).

Rules:

* Software never creates, signs, extends or fixes an approval or prerequisite record; only the named owner moves a record (docs/prerequisites.yaml, approvals/README.md).
* A missing input blocks activation of the affected capability only; it never blocks software work and never becomes a code stub.
* currentState is copied from docs/prerequisites.yaml (worst state of the mapped PRQ records). Entries without a PRQ record are UNKNOWN and proposed: they are proposed additions to the prerequisite register, not requests that were sent. relatedPrq names records that touch the same topic but do not cover the entry; it never sets the state.
* Activation ids use the AIN-NN prefix so they never collide with the invariant ids ACT-01..ACT-05 of docs/requirements/catalog.yaml.
* Activation steps name commands that the listed work packages deliver; until those packages land the commands do not exist and the step cannot run. CAPABILITY= values are capability ids of docs/followon/capabilities.yaml.
* A missing BAA is not missing code, and an adapter stub is not a missing BAA: software gaps are tracked in [`GAP_CLOSURE.md`](GAP_CLOSURE.md), never here.
* No paid test, PHI access, notification, live call, routing change, production mutation or release runs from a safe local default (OPS-05); every step below that touches an external system requires the named approval first.

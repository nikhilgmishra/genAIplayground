# WP-11 data-flow rows (draft, phase C): media path, CallBinding, recording

Drafted by WP-11 for the flows it adds; the phase C data-flows owner (WP-17) merges them into
`docs/privacy/data-flow-inventory.md`. Implemented and exercised against the local emulators only (SYNTHETIC callers:
WebRTC test participants publishing a tone). No carrier, real caller or AWS resource has been involved.

| ID | Flow | Data | Source -> destination | Storage and protection | Access | Retention / deletion | Logs and metrics | Status |
|---|---|---|---|---|---|---|---|---|
| DF-WP11-01 | Caller audio into the runtime | Caller speech audio frames (PHI-capable) | Carrier / livekit-sip or WebRTC -> livekit-server -> media worker job process (memory) | WebRTC (DTLS-SRTP) to the media plane; frames in process memory only; forwarded to an in-process tap only while consent permits it | The worker job process of the call | Not persisted by the worker | Content-free media health: call phase, inbound frame count and peak level (`vsp.mediaHealth` attribute) | Software `VERIFIED_LOCAL` (WP-11); environment `NOT_CONFIGURED` |
| DF-WP11-02 | Runtime output audio | Approved speech segments (later packages), comfort noise | Media worker -> livekit-server -> caller | Generation-fenced playback queue in memory | The caller and room participants | Not persisted | None | Software `VERIFIED_LOCAL` (WP-11) |
| DF-WP11-03 | CallBinding issuance, heartbeat and room claims | Room name (INTERNAL; can carry a caller number on SIP dispatch), room server id, job id, agent identity, worker instance, the SIP party's `sip.callID` and identity (a livekit-sip identity can carry the caller number), claim (binding id, generation, fencing token), processing directive (consent values, versions, template ids) | Media worker -> gateway media routes (HTTPS, runtime OAuth token) -> CallBindingService -> DynamoDB binding table; gateway -> livekit-server API (Twirp) | Binding record with the room name as SHA-256 only, the room server id and the carrier party as a SHA-256 identity digest, the session reference sealed with AES-256-GCM (AAD bound to tenant and interaction), conditional writes; the room claim (room server id -> interaction, carrier, party digest) and the carrier index (carrier interaction -> interaction, room server id) are first-writer-wins items keyed by namespaced SHA-256 digests; the first-bind lease (interaction, an opaque request id, a deadline) is a conditional item under a digest key; TTL = binding expiry + 1 day (indexes 2 days) | Gateway (CallBindingService); WP-14 resolves the session for runtime tool calls in process | DynamoDB TTL after the call; audit events per issuance, refusal (room mismatch, caller gone, carrier changed), re-bind, lifecycle change, supervisor end and decline | Audit actions `call.binding.*`, `call.lifecycle.*` (including `call.lifecycle.caller_gone`), `media.consent.declined`, `media.processing.mismatch`; logs carry reason codes and opaque ids, never a room name, identity or caller number | Software `VERIFIED_LOCAL` (WP-11); environment `NOT_CONFIGURED` |
| DF-WP11-04 | Call recording | Caller and runtime audio tracks (PHI-capable), recorded only under GRANTED or NOT_REQUIRED consent | livekit-server -> egress service (TrackEgress, Ogg/Opus) -> the egress service's configured object storage under `calls/<interactionId>/<bindingId>/` | Object storage of the egress service (locally MinIO; in AWS encryption, Object Lock and access to be decided, privacy review) | Recording reviewers (later packages; RESTRICTED_QA_MEDIA class) | Retention class RESTRICTED_QA_MEDIA (90 days in the sandbox configuration); deletion with the call's retention (WP-44) | Egress ids in the readout; no audio in logs | Software `VERIFIED_LOCAL` (WP-11, start/stop/decline against the local egress service); environment `NOT_CONFIGURED` |
| DF-WP11-05 | Processing readout | MediaProcessingState: opaque tenant, interaction and binding ids, tap phases, egress id, consent values and versions, disclosure template id, mismatch | Media worker -> agent participant attribute `vsp.mediaProcessing` (room participants) and -> gateway (`/processing` on every reconciliation tick; the answer carries the current processing directive; a mismatch is recorded on the binding record) | Participant attribute in the media plane for the call's lifetime; mismatch and the last consent version answered to the owner on the binding record | Room participants (opaque ids only); the gateway | Ends with the room; binding record TTL | `media.processing.mismatch` audit and warn log with the reason code | Software `VERIFIED_LOCAL` (WP-11) |
| DF-WP11-06 | Runtime credential | OAuth client credentials of the conversation runtime (VERIFICATION_SECRET class) and the access token | Media worker -> IdP token endpoint (egress transport); gateway -> IdP JWKS | Client secret injected into the worker's environment from the secret store; token cached in memory until shortly before expiry | The worker process; the gateway verifier | Token lifetime of the IdP (300 s locally) | Never logged | Software `VERIFIED_LOCAL` (WP-11, Keycloak); environment `NOT_CONFIGURED` |
| DF-WP11-07 | DTMF navigation | Caller key presses (can be a one-time code during secure entry) | livekit-sip / WebRTC -> livekit-server -> media worker DTMF menu or secure collector | Memory only | The menu (action names) or the secure collector (WP-12) | Not persisted | Action name only (`media.menu`), never the digit | Software `VERIFIED_LOCAL` (WP-11) |
| DF-WP11-08 | Egress list observation | The room's egress list as the egress API reports it: egress ids, track ids, file paths, status (no audio) | Media worker -> livekit-server Egress API (`ListEgress`, egress-classified transport) on every reconciliation tick, with or without a recorder of its own (observe-only client when recording is disabled) | Memory only | The worker job process of the call | Not persisted | Mismatch reason codes only (`FOREIGN_RECORDER_ACTIVE`, `RECORDER_STATE_UNKNOWN`) | Software `VERIFIED_LOCAL` (WP-11) |
| DF-WP11-09 | Supervisor end of a call whose caller left | Room name and server id, the room's participants (kinds and states), the call's binding record | MediaPlaneSupervisor -> livekit-server API (ListRooms, ListParticipants, ListDispatch) -> CallBindingService.endRoom -> DynamoDB binding table and SessionService | Binding record set ENDED; session ended; pending actions voided | Gateway (platform-internal, no runtime credential) | As DF-WP11-03 | `call.lifecycle.caller_gone` audit; `calls.supervisor.call_ended` info log (reason code only) | Software `IMPLEMENTED` (WP-11; the supervisor loop is scheduled by WP-17) |
| DF-WP11-10 | A room's person request | The room's server id, the platform interaction id, the request's reason code and language (standard) or the deterministic safety signals (rule ids and enum fields, never the caller's words) and locale (safety), request time, attempt count, and once accepted the handoff id, trusted destination id and speech template id | Gateway human and safety routes and the supervisor's route -> CallBindingService -> DynamoDB binding table (`cbp#` sha256 key of tenant and room server id) | Conditional item, compare-and-swap updates; no room name, caller number or content; TTL two days (cleanup only) | Gateway (platform-internal): the session-less routes, every bind, the supervisor | TTL two days after the last request | The routes' audit events (reason codes, interaction id); no log of the signals | Software `VERIFIED_LOCAL` (WP-11) |
| DF-WP11-11 | Call recorders kept for recovery | The egress ids the call's owners reported in their readouts, per binding id (no audio, no file path) | Media worker readout -> gateway `/processing` -> call record (`recorders`) -> the next owner's bind answer (`adoptableRecorders`) | Inside the call record (DynamoDB, conditional writes), at most 32 entries | Gateway; the call's next owner | With the call record (binding expiry plus a day) | None | Software `VERIFIED_LOCAL` (WP-11) |
| DF-WP11-12 | Recorder check of a job refused into a person route | Request: room name (INTERNAL; can carry a caller number on SIP dispatch), job id, agent identity, an optional mismatch reason code. Answer: the call's interaction id, its processing directive (consent values and versions, template ids) and the egress ids its owners reported (no audio, no file path, no claim) | Media worker -> gateway `/media/v1/calls/recorders` (runtime credential; the job is checked with livekit-server as for a bind) -> call record (read; a reported mismatch is written as `lastMismatch`) | Inside the call record (DynamoDB, conditional writes); TLS to the gateway | The runtime holding the room's dispatched job (its agent present) | With the call record | `calls.processing.mismatch` (reason code only) and the `media.processing.mismatch` audit event (opaque ids, reason code); the worker logs `media.recording.settlement_*` and `media.processing.mismatch` with reason codes only | Software `VERIFIED_LOCAL` (WP-11) |

# WP-04 proposed data flows: inbound event inbox, route-audit journal, independent audit export

Engineering draft by WP-04 for privacy and security review, to be merged into
[`docs/privacy/data-flow-inventory.md`](../../data-flow-inventory.md) by the phase integration package. It is
not a risk analysis or a compliance determination. Every flow below is implemented and exercised against
protocol emulators only (Layer 2, SYNTHETIC data); none is configured in any environment (NOT_CONFIGURED).
Retention durations marked "approval" are not invented here: the code refuses to run without an approved
value or takes it from the source profile, which needs approval per source.

| Flow | Data | Source -> destination | Storage and protection | Access | Retention / deletion | Logs and metrics |
|---|---|---|---|---|---|---|
| Inbound vendor event (webhook, delivery receipt, CDC push) | Raw event body as sent by the vendor; may contain PHI (identifiers, message status, case fields) | Vendor -> gateway `POST /v1/ingress/:sourceId/events` -> `inbound_events` (Aurora) | Authenticated before persistence; body sealed with a per-event KMS data key (AES-256-GCM, encryption context and AAD bound to tenant, source, event id, payload digest); stored only in restricted ciphertext columns; FORCE RLS per tenant | Gateway role: insert, identity and digest columns only; console role: metadata and replay columns, never the payload; worker role: decrypts to process; auditor: none | Raw payload purged after the source profile's `rawRetentionDays` (approval per source) once the row is terminal; digest, ids, schema, auth mechanism and credential version kept as evidence | Source ids (field `integration`), inbox ids, decisions (`outcome`), payload digests and reason codes; never bodies, tokens, signatures or secrets (the verifying credential version is on the row and in the audit event, not in logs). `vsp_inbox_*` metrics without tenant or subject labels |
| LiveKit server webhook (room and participant lifecycle) | Event JSON as livekit-server sends it: room sid and name, timing, codec list and the room's TURN credential (`room.turnPassword`); participant events would add identities | livekit-server (media plane) -> gateway `POST /v1/ingress/:sourceId/events` -> `inbound_events` | As the vendor event above: HS256 JWT binding the body's SHA-256 verified before persistence, body sealed in the restricted columns; the TURN credential is a secret and stays only in the sealed payload | As above | As above (`rawRetentionDays` of the LiveKit source, approval) | As above: never the payload, the token or the API secret (Layer 2: `ingress/livekit-webhook.test.ts`) |
| Inbound stream record (existing Kinesis or Kafka/MSK stream) | As above | Tenant stream -> worker `StreamIngestor` -> `inbound_events` | As above; checkpoints and gaps in `inbox_stream_checkpoints` / `inbox_stream_gaps` (positions only) | Worker | As above | Positions, lag and gap counts only |
| Inbound credentials | Webhook signing secrets, shared bearer secrets, pinned certificate fingerprints | Secrets Manager -> gateway memory (bounded cache) | Never stored in the inbox, logs or errors; only the Secrets Manager version id is recorded per event | Gateway task role (`secretsmanager:GetSecretValue` on the source's secret) | Rotation through AWSCURRENT / AWSPREVIOUS / AWSPENDING with a bounded overlap | Version ids only |
| Operator replay of an inbound event | Operator staff ref, reason code, MFA time | Console -> `inbound_replays`, `audit_outbox` | Audit event written first in the same transaction | Console role | Follows the audit retention class | `inbox.replay` audit event (codes and opaque ids) |
| Route-audit journal | Audit event input of a human or safety route (opaque ids, action codes, reason codes; no free text, schema-enforced) | Gateway / worker -> `audit_deferred` (Aurora); fallback -> DynamoDB journal table | DynamoDB item carries the same digest-checked input; PostgreSQL FORCE RLS | Runtime, console and worker roles (insert, select, state columns); auditor read | Rows stay as evidence (RECORDED / DROPPED with the event ids); DynamoDB entries marked drained; retention of the DynamoDB table is a Terraform decision (WP-39) | `audit.journal.*` logs and `vsp_audit_journal_*` metrics: codes, opaque ids, counts |
| Route intents and reconciliations | Opaque call, correlation and incident ids; route kind | Gateway / handoff -> `route_audit_intents`; worker -> `route_audit_reconciliations`, `audit_outbox` markers | FORCE RLS | Runtime / console / worker insert; auditor and verifier read | Follows the audit retention class | `vsp_route_audit_reconciled_total` |
| Independent audit export | Audit events (schema-enforced: opaque ids, codes, digests, evidence pointers) and signed manifests | Worker (exporter identity) -> S3 Object Lock bucket in the audit account | Object Lock retention, SSE-KMS (audit-account key), checksums, manifest signatures (audit KMS key, `ECDSA_SHA_256`) | Exporter: put only; verifier: list / get and public key only; nobody deletes before retention | `SECURITY_AUDIT` retention needs counsel approval (the sink refuses `null`) | Manifest ids, sequences and counts |
| Inbound replay keys | SHA-256 of (source, token id) and the SHA-256 of the bytes the token first authenticated; never the token | Gateway / worker -> `inbound_replay_keys` (Aurora, migration 2043) | FORCE RLS per tenant; immutable; deletable only once expired | Runtime and worker | Until the token expires, then purged by the worker | `inbox.replay_refused` (source id and reason code) |
| Credential promotion observations | Credential reference (secret ARN, configuration) and Secrets Manager version ids with observation times | Gateway / worker -> `ingress_credential_promotions` (Aurora, migration 2044) | Append-only (only the last observation moves forward) | Runtime and worker write; console reads | Kept (one row per credential version) | None (no key material) |
| Verifier sink session | Temporary list/get credentials scoped to the audit bucket (local: MinIO STS session policy; AWS: the verifier task role) | STS -> verifier memory | Never logged or stored | Verifier | Session lifetime (15 min) | None |
| Verifier report | Finding codes, stream names, sequences, opaque ids, counts per reconciliation source (`expected`, `observed`, `unverified`, `discrepancies`) | Verifier task -> stdout / JSON file / metrics | Content-free by construction | Security operations | Per incident record | `vsp_audit_verifier_runs_total`, `vsp_audit_reconciliation_discrepancies_total` |

Raw replay payloads are kept past their retention while a legal hold applies (`legal_holds`, any data class;
a subject-scoped hold keeps the tenant's payloads because inbound rows carry no subject).

Open points for review: retention per inbound source (raw replay window; the dataset `inbound_raw_payloads` is
not yet registered with an approved duration in the retention registry), the DynamoDB journal table's TTL and
encryption key, the audit-account bucket's retention and Object Lock mode (AIN-01, AIN-03), and the verifier
task's identity (WP-39).

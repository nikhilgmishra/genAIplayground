# WP-05 proposed data flows: caller and workforce identity

Engineering draft by WP-05 for privacy and security review, to be merged into
[`docs/privacy/data-flow-inventory.md`](../../data-flow-inventory.md) by the phase integration package. It is
not a risk analysis or a compliance determination. Every flow is implemented and exercised against local
Keycloak and postgres:16 with SYNTHETIC identities only; none is configured in any environment
(NOT_CONFIGURED). Retention periods need approval; the tables are not yet registered with the retention job.

| Flow | Data | Source -> destination | Storage and protection | Access | Retention / deletion | Logs and metrics |
|---|---|---|---|---|---|---|
| Workforce sign-in | Authorization code, state, nonce, PKCE verifier and challenge, redirect URI | Browser <-> console API <-> workforce IdP | The start stores nothing: nonce hash, challenge, a redirect digest and the lifetime travel in the sealed state (HMAC, tenant and issuer bound; nothing secret in it). The exchange records the state's single use (`console_login_transactions`: state hash, nonce hash, challenge, redirect, inserted consumed); TLS to the IdP over the egress-classified transport | Console API only | Single-use rows are deleted by the session sweeper in bounded batches once their state has expired; the database refuses to delete a live one (migration 2052) | Reason codes and correlation ids; never code, state, nonce or verifier |
| Workforce ID token | Issuer, subject, membership claim (the console client's roles), amr, auth_time, session id | Workforce IdP -> console API memory | Not stored; issuer and subject as digests, roles derived from the membership claim stored on the session row | Console API only | Not retained | Staff id (opaque), roles, reason codes |
| Console session | Bearer hash, family id, staff id, roles, activity and expiry times, refresh-in-flight (claim) time, sealed IdP refresh token | Console API -> `console_sessions` (Aurora) | Bearer stored as SHA-256 only; refresh token sealed with AES-256-GCM (key id per row, AAD session hash); revocation one way | Console API role | Ends at revocation, idle or absolute expiry; rows deletable after expiry (retention registration open) | Session events audited with reason codes (`console.auth.*`); a terminal closure whose audit write fails is applied without its events (it only revokes and suspends), which are then appended on their own, and the error log `console.sso.terminal_audit_unwritten` names any still missing |
| Offboarding check | Sealed refresh token (unsealed in memory), introspection result (active, subject, groups; an absent groups claim is read as no groups) | Console API -> workforce IdP introspection and revocation endpoints | TLS; not stored beyond the session's last check time and roles | Console API only | Not retained | `STAFF_DEPROVISIONED`, `STAFF_NOT_PROVISIONED`, `STAFF_ACTIVE_STATE_UNVERIFIED` reason codes |
| Break-glass and access reviews | Requester, decider, reviewer staff ids, reason codes, opaque ticket reference, times, outcomes | Console -> `console_break_glass_requests`, `console_break_glass_grants`, `console_access_reviews` | Database separation-of-duty checks; no free text | Security admins (decide, review), requester (own requests), auditors (reviews, read) | Audit-evidence retention (approval open) | Audit events with typed opaque references |
| Recovery identities | Custodian staff id, public P-256 JWK, attestation reference, roles, enrollment challenge (hash), holder confirmation time, suspension reason, activation challenge and request nonce (hashes), signatures | Security admins and the holder's own SSO session -> `console_recovery_identities`, `console_recovery_activations`; the holder's latest positive IdP evidence is read from `console_sessions` (time and roles of the newest SSO confirmation) | Public keys only (private keys stay on custodian hardware); one-time enrollment challenge shown once to the proposer and stored as a hash; single-use activation challenges and request nonces stored as hashes; at most 3 pending and 20 per hour per identity, counted over requests signed by the custodian | Security admins (auditor read without the challenge hash) | Revoked and suspended identities and activations kept for audit (activations are evidence of the recovery path); `console_sessions` retention must be at least `holderSsoMaxAgeSeconds` (14 days) or custodians lose the path early | Audit events with typed opaque references (`console.recovery_identity.suspended` / `reinstated`) |
| Anonymous sign-in refusals | Action, reason code, correlation id, a suppressed count | Console exchange endpoint -> audit log through the anonymous audit budget (per instance memory window) | At most one audit event per action and reason per 60 s window per instance; the count of the refusals suppressed in between rides on the next event; one log line per window | Auditors | Audit retention | Content-free: no code, state, verifier, token or IdP subject |
| Caller session activity and basis | `lastActivityAt`, `lapsedActorId`, processing basis (kind, purpose, approval ref) | Identity service -> session record (DynamoDB) | Existing session record; no new data class; actor id is an opaque id | Gateway, identity service | Session TTL (unchanged) | `identity.session.idle_expired`, `identity.verification.idp_unavailable` content-free logs |

Open points for review: retention periods for the console session and login tables and for break-glass,
access-review and recovery records; the jurisdiction and processing bases per role (counsel input); sealing
key custody and rotation for the IdP refresh tokens.

# Capacity and cost model (illustrative)

**Every input on this page is an illustrative planning assumption copied from spec section 12.**
None is measured company traffic, a vendor promise, a quote, a rate card or a contract term.
Sensitivity figures are arithmetic, not prices. The model is reproduced by
[`../scripts/capacity_model.py`](../scripts/capacity_model.py) (standard-library Python, no
network), which recomputes every figure, prints a table and asserts the specification's rounded
figures within tolerance; it exits non-zero if any figure drifts.

```bash
python3 scripts/capacity_model.py              # table + checks (exit 0 = all spec figures reproduced)
python3 scripts/capacity_model.py --markdown   # the tables embedded below
python3 scripts/capacity_model.py --json       # machine-readable inputs, figures and checks
```

`platform/test/docs/docs-pack.test.ts` re-runs the script and fails if the tables below differ
from its output.

## Reading the figures

* **Average versus busy hour.** About 139 simultaneous calls on a 24-hour average and about 278
  if arrivals concentrate in 12 hours hide the busy hour: 3,750 arrivals in the busiest hour at
  8 minutes is about 500 concurrent calls. Threefold stress gives 1,500; the contracted target of
  2,000 leaves about 1.33x headroom over stress; the 3,000 surge target is tested separately with
  controlled admission (`AdmissionController`, `platform/src/ops`).
* **Gateway load.** At 2,000 active sessions and one tool request every 15 seconds the gateway
  sees about 133 requests per second on average. The sustained test target of at least 400 is
  3x that average, plus larger bounded bursts.
* **Call setup.** One call every 8 minutes per slot at 2,000 occupied slots implies about 4.17
  call starts per second on average; real bursts and call-setup constraints need independent
  tests.
* **Human capacity.** At 20 % handoff the busy hour yields 750 human arrivals, 150 continuously
  busy agents at 12 minutes, and roughly 268 scheduled agents at 80 % occupancy and 30 %
  shrinkage; at 10 % handoff about 134. These are shortcuts "before more detailed queueing
  analysis" (spec section 12).
* **AI outage.** With the same shortcut, a sudden 100 % AI outage in the busy hour would need
  about 750 continuously busy agents (about 1,339 scheduled). This is a derived illustration, not
  a spec figure: a small residual queue cannot absorb it, which is why the outage service mode
  prioritises safety and urgent queues ([`RUNBOOKS/ai-off-route.md`](RUNBOOKS/ai-off-route.md)).
* **Erlang C illustration.** The Erlang C table shows the idealised waiting probability at the
  occupancy-shortcut head-count. Erlang C assumes Poisson arrivals, exponential handle times, no
  abandonment, no retrials and infinite patience; real contact centres violate all of these.
  **Workforce modelling with measured distributions, abandonment and service-level targets set
  by support operations is required**; the service-level target is UNKNOWN (VQ-OPS-03).
* **Statistics.** Zero failures in 3,000 approximately independent opportunities gives a rough
  95 % upper bound near 0.1 % on the failure rate, not proof of perfection (spec section 14).

## Cost model structure

Total cost = telephone minutes and overlapping transfer legs + AI voice charges + model usage
where separately billed + human staffing + platform licences + storage + logs + workflows +
network + security + support. Avoid double-counting bundled components (for example, AI voice
charges that already include ASR, TTS or model usage). No rate is filled in here: finance supplies
rate cards (PRQ-010, `docs/release/sandbox-cost-inputs.yaml` for the sandbox method).

| Rule | Where enforced |
|---|---|
| Track budgets by environment, cohort, workflow and vendor | `BudgetService` (`platform/src/ops/ports.ts`) |
| Measure cost per verified resolution, not only per minute | Scorecard and dashboards (planned) |
| Alerts and prepaid balances are not hard caps; vendor metering is delayed | `BudgetStatus.projectedUsd` includes a metering-delay projection |
| Budget exhaustion stops new nonessential automation and routes callers to approved continuity service | `AdmissionController` continuity routes |
| An active safety handoff is never disconnected to enforce a financial limit; a bounded safety reserve and escalation owner are approved before launch | `safetyReserveUsd`, `safetyReserveSessions`; [`RUNBOOKS/unexpected-spending.md`](RUNBOOKS/unexpected-spending.md) |
| No coding agent enables billing, buys numbers, runs billable simulations, starts large exports, increases quotas with cost commitments or deploys chargeable capacity without a specific estimate and approval | OPS-05; [`release/approval-requests.md`](release/approval-requests.md) |
